# MoE 训练手册 · 中文全译

这是 Hugging Face 与 NovaSky 的《MoE Training Handbook》全文中文翻译。原文是一篇可以动手照做的工程手册：所有数字都来自 8×H100 上的真实运行，讲的是「这一层的每个部件怎么选、每个开关到底把时间花在哪」。

- 原文：<https://huggingface.co/spaces/huggingface/moe-blogpost>
- 代码基准：[Megatron](https://github.com/NVIDIA/Megatron-LM) commit `d6316eb45`
- 规模：5 章 + 附录，正文约 5.1 万英文词
- 翻译模型：DeepSeek `deepseek-flash`（2026-11）

## 怎么读

这篇手册的组织方式是一条「从外到内、再从内到外」的路线：

1. **先建直觉**（第 1 章）：为什么 MoE 值得做，参数里有多少是「总参」、多少是「激活」。
2. **先跑起来**（第 2 章）：测硬件、建镜像、分词，先训一个稠密基线，再换成一个 MoE。
3. **再调每一层**（第 3 章，最长）：路由器怎么打分、怎么均衡、专家多少个多宽、块怎么接、优化器和 MTP 怎么配、最后系统工程怎么把时间拿回来。
4. **然后服务出去**（第 4 章）：训练时的选择在推理时哪些还成立、哪些要翻案。
5. **最后收口**（第 5 章）：一份可以直接抄的推荐参数清单。

## 关于图

原站的图都是 React 交互组件（可以拖动、切换），无法在 Markdown 与 PDF 里复现。本译本的处理方式是：**保留图号与图注，正文里标注「（原站为交互图，此处从略）」**；凡是有数字的结论，都在正文里用文字说清楚了，不依赖看图。

## 一个提醒

手册里的数字几乎都来自**单节点 8×H100**（少数是两节点）。它给的不是「标准答案」，而是「同一套测量方法下，不同选择之间的相对差距」。照抄参数之前先按第 2 章把硬件测一遍、按第 3 章把监控打开——不同集群、不同互联，最优点会移动。
